How to Build and Host a Personal Website with Cloudflare

A beginner-friendly walkthrough of preparing a static website, publishing it on Cloudflare and connecting a custom domain.

A personal website can be a simple home for your name, profile photo, projects and social links. You do not need a complex framework to publish one. This guide follows the general approach used for this site: prepare static files, upload them to Cloudflare and connect a domain.

Cost clarification: Static hosting can be free within Cloudflare's applicable limits. A custom domain is a separate purchase and may have renewal costs. You can test the website on the Cloudflare-provided address before connecting a purchased domain.

1. Plan the page before writing code

Start with one clear purpose. For a personal site, visitors should immediately understand who you are and where to go next. A simple first version might include a name, short introduction, profile image, links to your public accounts and a contact option. Add project or article sections only when you have useful material for them.

Write down the links you want to publish and check that they point to your actual profiles. Avoid putting private information on a public page.

2. Create the website files

A basic static website usually has an index.html file, optional CSS and JavaScript files, and any images it uses. HTML describes the page, CSS controls its appearance, and JavaScript adds features such as a theme switcher or share button.

my-website/
  index.html
  profile.jpg
  favicon.svg
  sitemap.xml
  robots.txt

The index.html file should be at the top level of the upload. If it is hidden inside another folder, your hosting service may not find the homepage at the expected address.

3. Check the site locally

Open index.html in a browser. Check your name, image, links and mobile layout. Use a real phone as well as a desktop if you can. Try every button, including contact and share features. Some browser features behave differently when a file is opened locally; verify them again after deployment over HTTPS.

Before publishing, make sure the photo file name exactly matches the name used in your HTML. On Windows, hidden file extensions can make profile.jpg.jpg look deceptively similar to profile.jpg.

4. Upload the static files to Cloudflare

In the Cloudflare dashboard, create a project that supports static asset uploads, then upload the contents of your website folder. Cloudflare's interface and deployment options can change, so follow the current on-screen instructions for your project type. After deployment, open the Cloudflare-provided website address and test the page before changing your domain settings.

If you are updating an existing site, deploy the new files to the same Worker or project rather than creating a separate one. Keep a backup of the previous working version.

5. Connect your own domain (optional)

A domain is the address visitors type into their browser. Hosting stores and serves the site; DNS helps the domain reach that hosting. If you own a domain, add it through your Cloudflare project's custom-domain settings and follow the prompts.

An older DNS record may already point your domain to a previous hosting service or a placeholder page. A conflicting record may need to be replaced before the new custom domain can be attached. Check which exact hostname is affected, and do not delete unrelated mail or verification records.

When Cloudflare reports the custom domain is connected, test the HTTPS address in a new tab. Keep the provided project address available as a troubleshooting option.

6. Add discoverability basics

Give each page a descriptive title and a short meta description. Link related pages together and include a sitemap.xml file when you publish several pages. Add your main website link to your public social profiles so people have a consistent way to find it.

7. Maintain the website

Keep a copy of the original website files. When you change a photo, add an article or update a link, upload the changed files to the existing deployment and test again. A working website is a starting point; useful content and regular maintenance make it more valuable over time.

Common questions

Do I need GitHub?

No. A direct static-file upload is enough for a simple site if your hosting project supports it. Version control becomes more useful as your website grows.

Is a custom domain required?

No. You can publish and test using the address provided by your hosting service, then add a domain later.

Can I earn money immediately?

Publishing a website does not create automatic income. Build helpful, original content and an audience before considering advertising.
